# On-device personal finance

Open **Personal finance** at the top of the existing gateway screen. This is an additional Expo Router route; the original gateway remains available. The finance feature makes no backend requests. No sample records are seeded. SQLite stores extracted fields, not complete SMS bodies.

## Android setup and distribution gate

The local module in `modules/finance-sms` is autolinked into an Android development build. Expo Go cannot receive SMS. Install dependencies, then use `npx expo run:android` with Java/Android SDK installed, or create a development build with EAS. Native projects are generated by Expo; no generated Android files are maintained here.

SMS access ships disabled: `plugins/withFinanceSms` omits RECEIVE_SMS unless its `policyReady` option is true. `extra.financeSmsPolicyReady` separately gates the runtime request. Set both only after the intended distribution policy requirements have been satisfied. Never interpret either flag as evidence of Google approval. No READ_SMS or SEND_SMS is requested.

Before Play distribution, establish eligibility for the SMS-based financial management exception, complete the Play Console SMS Permissions Declaration Form, obtain any required approval, publish a privacy policy with developer contact and retention/deletion terms, link it in the listing, and complete Data Safety disclosures. Financial SMS management must qualify as critical core functionality; adding a finance screen to a messaging gateway does not guarantee eligibility. If this app does not qualify, leave the gate disabled and omit SMS permissions.

Policy reference: https://support.google.com/googleplay/android-developer/answer/10208820

The disclosure appears before Android's permission dialog. Consent is recorded by enabling the native preference only after the user agrees and grants Android permission. Disable pauses receipt. Delete-all pauses receipt and clears the native queue and finance tables. Revocation is checked when the screen refreshes.

## Lifecycle and limitations

The manifest receiver assembles multipart SMS and drops OTP/unrelated candidates before persistence. Relevant text is temporarily kept in app-private SharedPreferences so background receipt survives process restart; the foreground finance screen drains it every 2.5 seconds and on resume. SHA-256 IDs prevent repeat event insertion. Queue acknowledgement follows the SQLite commit, making replay after interruption safe. Reference/amount/account matching reconciles status updates. Reversed debit entries are excluded from expenses rather than counted as independent refund income. Distinct credit refunds remain income records.

SMS timestamps are used as transaction timestamps and are labeled as SMS receipt time in details. Message-specific dates are not parsed. Unknown formats may be missed, and the parser is conservative rather than a complete bank-format catalog. Independent payment-app settlement is never verified. Force-stop, OEM restrictions, permission revocation, or missing SMS delivery can prevent detection. Raw candidates remain queued until the finance screen is opened; uninstall removes local app storage. Android app backup is disabled to keep finance records off cloud backup.

## Verification

Run `npm run typecheck`, `npm run lint`, and `npm run test:finance`. Parser fixtures are synthetic, not device SMS simulation. On an Android emulator with the gate enabled for an authorized test build, send synthetic alerts using emulator SMS controls; check foreground notification, background receipt, process restart and duplicate replay. Check deny, permanent deny, revoke in settings, disable, delete-all, and relaunch. Test SQLite duplicate replay and reference reconciliation on-device. These device/database scenarios are a manual checklist, not claims of automated verification.
